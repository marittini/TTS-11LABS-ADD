ElevenLabs TTS Message Controls 4.3.6

설치
기존 ElevenLabs TTS Message Controls를 이 ZIP으로 교체하고 ME를 새로고침합니다.
이전 TTS 버전은 동시에 활성화하지 마세요.
확장 서랍 1.3.5는 그대로 사용합니다. 서랍 파일을 교체할 필요 없습니다.

TTS 퀵아이콘 통합
- Game/RP/Convo 음성 설정 패널 상단의 TTS 연결 스위치로 전체 방의 ME TTS 자체를 켜고 끕니다.
- 기존 별도 ME-TTS-Quick-Toggle 확장은 비활성화하세요. 이 버전에서 같은 기능을 제공합니다.
- 대사별 음성 버튼 표시 스위치는 RP 화면의 별도 설정입니다. TTS 연결 스위치와 다릅니다.
- 서버 설정을 새로 읽고 enabled만 변경하여 보이스/속도/프로필 등 다른 설정을 보존합니다.
- 저장 후 서버의 상태를 다시 확인하고 ME의 React Query TTS 설정 캐시도 동기화합니다.
- OFF 전환 시 확장이 재생 중인 음성을 정지합니다.
- ME의 캐시를 찾을 수 없는 환경에서는 설정 저장·확인 후 화면을 새로고침하여 반영합니다.
- 조회/저장 실패 시 성공한 상태로 표시하지 않고 상태 재확인 버튼을 제공합니다.
- 패널 재진입, 화면 포커스 복귀, ME 설정 변경을 통해 상태를 확인합니다.
- 서랍 먼저/나중 로딩, 패널 스위치 ON/OFF, 다른 설정 보존, 캐시 동기화, OFF 시 지침 제외, Game/Convo 패널, 실패 복구 및 새로고침 대체 경로 검증 통과.

호환 수정
- 확장 서랍은 생성 요청을 가로채지 않습니다. 원본 아이콘을 숨겨 서랍의 대체 버튼으로 실행합니다.
- 기존 TTS는 주기적으로 아이콘의 display를 다시 써서 서랍의 숨김과 충돌했습니다. 이제 표시 상태를 덮어쓰지 않습니다.
- 음성 설정 패널을 아이콘에서 분리하여 서랍에 아이콘을 넣어도 패널은 열립니다.
- 서랍의 합성 pointerdown은 아이콘 드래그로 취급하지 않습니다.
- 생성 요청에 담긴 chatId와 서버의 해당 채팅 mode로 음성 지침 적용 여부를 판단합니다. 화면 렌더링 상태와 오래된 현재 방 ID는 생성 주입을 막지 않습니다.
- 기존 generationGuide, 요청 헤더, RP smartResponse 조건을 유지합니다. 같은 TTS 지침을 중복 추가하지 않습니다.
- 설정 확인 실패 시 메인 텍스트 요청을 그대로 한 번 전달합니다. 유료 요청 자동 재시도는 없습니다.

UI
- 작은 파형 아이콘, 카드형 화자 선택, 대사별 버튼 표시 스위치.
- 독립 패널로 화면 경계 안에 배치. 320px 모바일/작은 세로 화면, 확대 및 키보드에 따른 visualViewport 변화 대응.
- 연결 탭의 ElevenLabs 설정 카드도 간격, 글자 크기, 입력 요소 스타일 정리.
- 기존 방별 화자 선택, 버튼 상태, 아이콘 위치 저장을 유지합니다.

기존 동작 유지
- Game/RP/Convo 채팅만 적용합니다. Gacha Forge/Noodle/Slurp 등 명시적 에이전트 요청과 지원하지 않는 채팅 mode는 제외합니다.
- 사용자 메시지와 사용자 번역 입력의 대괄호 표현은 유지합니다.
- 캐릭터 메시지/번역문의 대괄호 태그는 뒤 공백까지 숨깁니다. 실제 TTS 입력에는 남습니다.
- JSON 번역 요청은 TTS 보호 대상으로 바꾸지 않습니다.

검증
첨부된 확장 서랍 1.3.5 원본과 TTS를 로컬 Chromium 테스트 페이지에서 실행했습니다.
서랍을 먼저/나중에 불러온 경우 각각 아이콘 수집, 여러 스캔 이후 숨김 유지, 패널 열기/닫기, 방별 화자/버튼 설정 저장, 390px 및 320px 화면 경계 확인.
화면 모드가 잠시 없는 경우, 오래된 현재 방 ID, Game/RP/Convo 요청의 지침 주입, 기존 컨텍스트/헤더 보존, 에이전트 제외, Request 객체, TTS OFF, 준비 실패 시 단일 전송, 취소 요청, 중복 지침 방지 확인.
사용자/AI 표시와 사용자/JSON 번역 우회 회귀 검증 통과.
실제 사용자 서버와 ElevenLabs 유료 음성 생성은 실행하지 않았습니다.

진단 범위
소스와 재현 테스트에서 표시 충돌 및 주입 누락 조건을 확인했습니다.
사용자의 실제 환경에서 보고된 모든 컨텍스트 누락이 이 원인에서 비롯됐다고 단정하지 않습니다.
